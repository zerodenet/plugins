# 验证发布者对源码仓库的控制权

[English](source-control.md) · **简体中文**

登记和资料更新需要源码方同意。个人仓库所有者可直接提交；当自动化凭据可访问协作者权限接口时，具有 write、maintain 或 admin 权限的账号也可提交。插件中心仓库的 `GITHUB_TOKEN` 通常无法查询另一个仓库的协作者权限，因此 HTTP 403 不代表提交者没有写权限。

对于组织仓库、授权代为提交的账号，或协作者权限接口不可用的情况，源码维护者可在源码仓库**默认分支**提交公开的 `.github/marketplace-authorizations.json`。插件中心读取当前默认分支提交，再按固定 SHA 获取该文件，通过公开 GitHub API 核验。它不读取 Issue 指定的分支、文件地址或可执行程序。

## 为具体请求授权

1. 先创建登记或资料更新 Issue，提供固定发行元数据链接。
2. 在发布者仓库目录执行以下工具，检查生成的公开 JSON，然后将文件提交到发布者的默认分支。工具来自插件中心仓库检出目录，只读取公开 Issue，无需令牌。

```sh
python3 /path/to/plugins/scripts/source_authorization.py \
  --marketplace zerodenet/plugins --issue 7
```

结构示例中的数字 ID 和摘要需替换为工具实际生成的值：

```json
{
  "schema_version": 1,
  "authorizations": [
    {
      "marketplace": "zerodenet/plugins",
      "issue": 7,
      "actor_id": 123,
      "body_sha256": "<Issue 原始 UTF-8 正文的 SHA-256>"
    }
  ]
}
```

3. 源码提交公开后，编辑或重新打开原 Issue；插件中心推送或手动同步也会重试尚未完成的申请。

授权同时绑定插件中心仓库、Issue 编号、GitHub 数字作者 ID 和完整正文。因此不能用于其他账号、Issue、插件中心、发行链接或修改后的申请。正文变更后须重新生成并提交证明；评论和标签不会改变正文。工具保留其他授权，并替换同一插件中心、Issue、作者的旧证明。账号改名不会转移数字身份。

源码仓库转移仍须同时证明对原仓库和新仓库的控制权，两处都要同意这份请求。缺失或不匹配的证明会保留为 `status:needs-info`，不会自动放行。文件上限 16 KiB、100 条精确授权；拒绝符号链接、重复 JSON 字段及不限定范围的授权。

此公开文件只同意指定的插件中心登记请求，不授予仓库写权限、安装包信任或宿主权限，也不包含签名私钥或令牌。可在源码维护时清理旧条目。个人所有者及可核验协作者的原有提交方式仍受支持。
