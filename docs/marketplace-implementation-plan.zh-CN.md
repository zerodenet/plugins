# 统一插件市场实施计划

[English](marketplace-implementation-plan.md) · **简体中文**

状态：待实施。技术选择：Astro + Minted Directory Astro；参考 Ever Works 的列表与详情体验。本文确定后续改造目标，现有目录格式在迁移完成前仍然有效。

## 1. 首期目标与边界

- 一个统一市场入口，网站支持搜索、筛选、查看详情及发布/下载链接。
- ZBoard 与 ZNet Sink 请求同一查询接口，通过显式 host 参数取得不同的适配列表；不根据 IP、Referer 或 User-Agent 猜宿主。
- 中央登记一个插件产品及可信发布来源。作者在自己的仓库发布多宿主安装包及自动生成的发布清单。
- 安装、更新、包验证、权限、运行和卸载均属于宿主；中央不保存插件运行状态，不构建或执行第三方包。
- 首期不做 giscus、账号、个人主页、收藏、评分、支付和管理后台。

## 2. 技术与部署

- Astro + [Minted Directory Astro](https://github.com/masterkram/minted-directory-astro)：复用目录与内容组件，固定实际验收过的提交/依赖，保留 MIT 许可说明。
- [Ever Works](https://github.com/ever-works/directory-web-template)：参考信息层级、卡片和详情布局，不移植其服务端。直接复用任何代码前单独核对其许可证。
- Cloudflare Worker：在统一域名的 /api/ 下提供无数据库的只读过滤服务，读取构建时生成的市场快照。
- 静态页面与 API 建议由同一个 Worker 的静态资源功能部署，减少域名路由配置。GitHub Actions 负责构建发布；GitHub Pages 不是必须条件。如保留 Pages，需额外配置统一域名的 /api/ 路由。
- 网页和两端使用同一目录服务与快照，页面可预渲染详情，交互查询使用相同过滤规则；不存在分别维护的网页目录与宿主目录。
- GitHub 访问凭据仅存在于构建环境。在线查询不逐项请求 GitHub，不需要访客 token。

## 3. 数据与查询契约

### 三层声明

1. 注册：稳定 product ID、名称简介、仓库、可信发布者、许可证、发布清单发现约定。保留现有包身份与发布者归属，不靠同名自动合并。
2. 作者发布清单：版本/渠道、源提交、各目标宿主、包 ID、平台/API 要求、文件地址、大小、摘要与签名信息；工具从包声明生成，作者不重复手填。
3. 构建快照：汇总经校验的注册与发布信息，提供搜索/详情与适配查询；包括快照版本、生成时间和来源。它是派生数据，不成为第二份人工登记。

目录来源信任与包签名分别处理。不得将任意上游提交的公钥自动提升为可信发布者。新权限、密钥轮换、撤回和来源变更按明确治理处理；日常版本同步不能绕过这些检查。

### 接口草案（P1 固定正式字段）

- GET /api/plugins?host=zboard&q=...：仅返回支持 ZBoard 的产品及其适配目标。
- GET /api/plugins?host=znet-sink&q=...：仅返回客户端目标，不混入服务端包。
- GET /api/plugins：网站全量发现，分页返回。
- GET /api/plugins/:id?host=...：详情与该宿主目标；不适配时明确报告，不回退另一宿主。
- 可选 host_version、os、arch、channel 用于进一步过滤，默认 stable。未提供版本/平台时仅承诺宿主级适用，不标记已通过完整兼容判断。
- q、分类、分页及排序有统一语义。未知参数值有明确错误，缓存键包含所有有效过滤维度和快照版本；ETag 支持条件读取。
- 支持但无正式产物的源码条目可在网页发现，不作为可安装项返回；具体状态在契约中区分。

## 4. 实施阶段

### P0：盘点与冻结基线

- 记录中央仓库未提交修改，逐项识别既有提交流程工作，不覆盖或回退。
- 核对真实已发布目录、作者元数据及两端消费代码；不能仅凭本地旧文档决定 schema 版本。
- 验证 Minted 静态构建、JSON 数据接入、详情路由、搜索与许可，固定上游提交。
- 梳理旧 product/package 身份映射、现有发布记录及撤回规则。

验收：迁移矩阵、依赖清单与模板可运行基线明确。

### P1：统一注册、包声明与发布清单

- 定义版本化 schema 和兼容规则，单宿主作者仅声明自己的目标。
- 统一按产品登记，各目标分别声明兼容、权限和产物；保留已发布包 ID/版本/摘要。
- 更新中央校验、Issue 注册和审核流程，接续已有修改。中央管理稳定注册，日常版本由作者发布，不要求每次修改注册。
- 声明源码条目、稳定版、预发布、撤回、密钥变更、权限扩大等处理规则。

验收：单/双宿主样例通过；重复身份、越权密钥替换、错宿主、篡改元数据等负例被拒绝。

### P2：配套工具与示例

- 提供注册/发布元数据校验及清单生成工具，复用宿主现有打包机制，不在中央复制 runtime 或 SDK。
- 中央保留 schema、声明 fixture 与使用文档；可执行单宿主、双宿主示例及作者打包工作流放独立示例仓库，具体位置实施时确定。
- 工具从实际产物计算摘要/大小，验证清单与包身份一致，输出上传同一 GitHub Release 的清单。

验收：作者使用一次发布流程产生单/双目标清单；无私钥入库，无假版本/假链接；中央 CI 不执行提交包。

### P3：快照构建与统一过滤服务

- 构建任务读取注册和作者发布清单，设置数量/大小/超时边界，校验来源及元数据。
- 个别仓库暂时不可用时保留可用旧数据并标记新鲜度；明确撤回立即生效，不被旧缓存恢复。
- 实现 Worker 列表、详情与宿主/兼容过滤；网站与两端共享结果语义。
- 页面、API 和快照使用一致版本原子发布，保留上一版回滚能力；生成文件不进入人工维护目录。

验收：同一 URL 接口按 host 返回不同包列表；平台/版本、分页、预发布、无适配包、缓存隔离及失败回退均覆盖。

### P4：网站展示

- 列表：搜索、宿主/分类筛选、图标、名称、简介、发布者和适用标识。
- 详情：介绍、截图、宿主目标、版本、兼容要求、权限、文档/仓库/下载链接。
- 按 Ever Works 的信息布局调整 Minted，保留简洁风格和移动端完整阅读；不做虚构评分或安装量。
- 静态页面处理 Markdown/图片来源边界；远端内容不执行脚本。没有已验证产物时不显示可用安装按钮。

验收：真实已登记插件和标明测试身份的多宿主 fixture 完成页面验证；fixture 不进入生产市场。

### P5：两端接入与兼容迁移

- ZBoard 默认传 host=zboard，ZNet Sink 默认传 host=znet-sink，再传可用版本/平台信息。
- 两端适配发布清单与包选择，保留本地独立验证和授权流程。
- 如旧安装版本仍需兼容目录，仅从统一数据生成投影，规定退出条件，不人工双维护。

验收：各宿主仅显示自己的适用目标；真实签名包下载/验证/安装/升级按宿主测试，原安装数据与身份保留。没有真实双端包时不得宣布双端安装已验收。

### P6：部署与验收

- 配置定时/注册变化触发构建、Worker 静态资源及 API、自定义域名和回滚。
- 先验证预览环境，再发布；如缺账号/域名权限，只请求该项输入，不影响前置实现。
- 中央执行单元测试、目录校验、静态构建、接口及本地 Markdown 链接检查；两端分别遵循所在仓库检查要求。

验收：域名访问、搜索详情、双 host 请求、缓存更新、上游失败和回滚均有证据。分别记录代码、提交、推送、部署和实际安装结果。
