# 插件架构

[English](governance.md) · **简体中文**

本文定义 ZeroDeNet 插件的集成边界。项目维护与评审政策见[项目治理](../GOVERNANCE.zh-CN.md)。

## 职责

| 组件 | 负责内容 |
| --- | --- |
| 市场 | 插件发现、发布者信息、版本元数据和包分发 |
| 宿主插件管理器 | 准入、运行实例、配置、私有存储和生命周期操作 |
| 宿主核心服务 | 业务记录、授权策略和已提交的业务事务 |
| 插件 | 通过声明的宿主 API 提供集成逻辑与扩展界面 |

ZBoard 拥有账户、凭证、订单、权益、流量记录和节点配置发布。客户端宿主拥有自己的配置、系统权限、连接生命周期和受控内核操作。接入市场后，这些职责仍由各宿主承担。

## 能力模型

Manifest 声明插件需要的操作。宿主结合已支持的 API、调用者身份、资源范围、活动插件实例和核心策略进行校验。市场条目提供元数据，准入在宿主内部执行。

页面范围、运行组件和能力描述插件的不同部分。`admin` 页面不授予后台业务权限。对于 OAuth，核心注册开关和账户状态仍决定外部身份能否创建或访问账户。

插件使用有版本的专用接口。数据库连接、任意 SQL、管理员令牌、节点凭据和不受限的宿主命令不属于插件 API。

## 生命周期契约

| 操作 | 宿主职责 |
| --- | --- |
| 安装 | 准入前校验签名、包内容、宿主/API/平台兼容性和能力。 |
| 启用 | 准备运行时、核验身份并应用已提交配置，然后开放扩展入口。 |
| 升级 | 准备候选配置、数据迁移和运行时；提交切换，或在失败时保留旧安装。 |
| 停用 | 撤销实例的页面与调用会话，停止运行时。 |
| 卸载 | 按宿主保留策略移除程序资源。 |
| 清除数据 | 移除插件配置与私有数据，保留核心业务记录。 |

迁移顺序、版本、校验和与结果由宿主记录。恢复旧程序时，需要检查其与现有数据的兼容性。插件停止后，已完成的核心事务仍然有效。

ZBoard 当前提供宿主管理的加密 JSON 私有存储和声明式迁移。关系型扩展 schema 需要单独的宿主契约，插件不能自行创建或迁移核心表。

## 信任与隔离

目录签名确认索引来源，包签名确认制品来源与完整性。两种角色都由宿主管理信任，目录中附带的公钥不会自动获得信任。

ZBoard 当前将原生服务组件作为受信任代码放在独立进程中运行，不为任意第三方二进制提供 OS 沙箱。后续宿主需分别定义自己的运行时、系统权限和资源隔离模型。

## 扩展 API

新增能力的提案应明确授权、资源范围、幂等、完成语义、失败恢复，以及生命周期切换期间的行为。宿主先实现并验证契约，再由插件使用。

共享分发不引入跨产品全局权限。跨产品集成使用受控业务 API，插件存储和宿主会话保持独立。市场设计不向 Zero 内核增加插件 SPI。
