# 插件市场准入自动化

[English](automation.md) · **简体中文**

自动化只处理首次入驻申请，不轮询开发者仓库的新版本，也不会为每次发版创建 Issue 或 PR。

申请者提供一个正式入驻版本中固定的 marketplace-entry.json。工作流校验仓库与标签、源码提交、GitHub 记录的产物大小和摘要，并提取不含版本信息的目录条目。工作流不会检出贡献者代码，也不会执行安装包。

维护者在合并准入 PR 前审核插件立意、发布者与公钥归属、能力及界面上限、许可证、安全联系、迁移与卸载行为以及实际宿主证据。合并后，宿主直接从已登记仓库发现正式版、RC 和 Dev 发行。

常规发版和插件仓库基础资料更新不会触发市场流程。只有信任边界或资料/发行源契约变化时，才重新申请或提交专门的目录 PR。标签只描述申请状态，不发布插件版本，也不授予宿主能力。

工作流响应申请 Issue、准入 PR 完成、main 更新和手动协调；设计上不再存在定时发行同步。
