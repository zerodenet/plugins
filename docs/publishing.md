# 发布与上架规范

当前仓库尚未发布正式签名目录、包或官方发布者公钥。本文规定发布条件，不表示发布设施已经落地。共享目录 v2 见 [市场草案](marketplace-design.md)。

## 发布输入

每个发行版本记录源码提交、插件 ID、目标宿主、版本约束、SDK/桥协议、目标平台、能力、配置/数据兼容说明、制品摘要和测试证据。插件采用 SemVer；发布后的版本和制品地址不可替换内容，需要修复时发布新版本。

发布版本必须经过仓库检查、宿主安装/启停/升级/卸载验证和对应平台运行验证。认证插件还需记录真实第三方联调状态；没有真实 Client ID 的 fixture 测试不能当作第三方已验收。首次正式发布前复核 manifest 的 tested/recommended 版本声明，不能将开发宿主的展示版本当作全部同版本发行包都兼容。

多插件标签按 `zboard/oauth/v<version>` 等宿主/插件前缀区分。每个标签唯一定位源码提交；保留构建工具链版本、宿主打包器提交、文件清单与 SHA-256。正式发布不使用未提交修改或本地 workspace 替换依赖。

## 签名和制品

由维护者在受保护的发布环境提供签名私钥和发布者 ID。源码仓库只保存审核过的公开信息，不保存私钥；PR 检查不能获得发布密钥。

```sh
cd zboard/oauth
python3 scripts/package.py --zboard /path/to/zboard \
  --key /secure/publisher.key --key-id your-publisher --platform linux-amd64
```

`--dev-key` 固定使用 `oauth-local-dev`，不能作为正式发布者上架。正式公钥分发与轮换必须由维护者建立可信渠道，不能从待安装包自身取得信任。

仅打包 manifest 明确列出的 UI 和运行组件。测试源码、密钥、数据库、开发配置、Go workspace 和调试构建不进入安装包。OS 代码签名/公证与插件 Ed25519 签名分别验证；跨平台编译不证明目标平台能够运行。

## 市场目录

先发布不可变制品，再生成包含精确摘要的签名目录，最后验证宿主在线安装。安装器必须比对目录与包的身份、版本、发布者及宿主要求。不能在源码提交时提前放置虚构下载地址或未签名空目录冒充在线市场。

旧 ZBoard 使用 schema v1，目录最多 200 个插件 ID、每 ID 一条记录，有效期最多 31 天。多平台发布可在同一包放入多个受支持平台二进制，或维护明确的平台专用目录；不能往同一 v1 目录重复写入相同 ID。当前打包脚本一次只构建一个平台，不声称已实现多平台合包或自动市场发布。

当前 ZBoard 下载器只允许公开 HTTPS 443，并拒绝查询参数、重定向和环境代理。因此目录和安装包必须提供符合要求的直接下载地址；不能直接假定 GitHub Release 的下载跳转可用。目录过期需要重新签发，在自动续签和监控落地前由维护者负责。

目录撤回不删除已安装插件的业务数据。密钥泄露、恶意制品或严重缺陷应停止分发，公布受影响摘要和修复方案，并按宿主支持的处置能力执行；不能宣称当前已具备自动撤销机制。
