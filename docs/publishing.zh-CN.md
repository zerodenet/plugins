# 发布与插件市场准入

[English](publishing.md) · **简体中文**

## 首次入驻

开发者先在独立插件仓库根目录提供 `marketplace.json`，再发布一个正式签名版本，包含固定平台包、校验值、兼容声明、源码提交和 marketplace-entry.json，并使用该元数据链接申请市场准入，同时提供发布者归属、安全维护、宿主行为及所需能力上限的证据。

准入审核只登记稳定的发现与信任信息，不把入驻版本或后续版本复制到中心发行台账。

## 开发者自管版本生命周期

通过准入后，开发者无需再次提交市场 Issue，即可发布正式版、RC 和 Dev 版。每个可在线处理的发行必须：

- 沿用已登记的插件 ID、仓库、发布者 ID 和正式签名密钥；
- 遵循宿主安装包及元数据契约；
- 不超出登记的界面和能力上限；
- 发布不可变安装包及一个 marketplace-entry.json；
- RC 与 Dev 标记为预发行，正式版标记为普通发行。

宿主直接发现版本，提供频道和精确版本选择，检查兼容性，校验安装包签名及摘要，并执行安装、升级或降级。超出准入边界的发行会被拒绝，需要先更新市场登记。

使用一次性 CI 密钥签名的开发产物只用于隔离环境离线测试，不能进入市场。离线导入也继续支持私有、本地或不方便开源的插件。

## 更新目录

只有仓库迁移、发布者或密钥轮换、资料/发行源契约变更、新增宿主、扩大能力或界面边界以及撤回时，才回到市场处理。名称、说明、许可证和维护者等基础资料保留在插件仓库的 `marketplace.json`。这些是准入变更，不是版本发布。
