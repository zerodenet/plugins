# 发布与审核

[English](publishing.md) · **简体中文**

插件发行与市场收录是两个独立动作。发布者只构建本次发行的插件；市场审核元数据，不重新编译第三方源码。

## 发布者流程

在独立仓库开发和测试。确定 `vX.Y.Z` 版本，使用生产发布者密钥签名各平台安装包，并附源码提交、校验和、字节数及兼容声明发布。私钥始终保留在版本控制之外，公开发行严禁使用 CI 开发密钥。

[OAuth for ZBoard](https://github.com/higanbana986/zboard-oauth)提供标签触发检查、五平台打包与自动生成的 `marketplace-entry.json`。发行环境配置见该仓库指南。其他发布者可使用自己的工具，但产物必须符合宿主安装包契约。

## 市场流程

使用问题表单或 PR 模板提交发行版本。只更新 `catalogs/zboard.json` 或 `catalogs/znet-sink.json` 内的对应条目，并保留历史发行记录。条目模板中的示例值必须全部替换。

CI 校验仓库元数据，不执行提交的安装包。维护者独立核实发布者及公钥归属、发行与源码关系、包签名、摘要和宿主测试证据。仅通过源目录校验不足以证明版本可安装。

## 签名安装目录

源目录不能直接用于安装。分发发布者需选择已审核、兼容宿主和平台的产物，生成宿主格式的签名目录，使用宿主接受的 HTTPS 下载路径提供文件，并在过期前续签。市场目录密钥与插件发布者密钥分别管理。

ZBoard 当前接受签名目录 v1 及不经过重定向的直接 HTTPS 安装包地址。GitHub Release 产物地址会重定向；现有宿主须离线导入或使用兼容的直连下载镜像，直到宿主实现重定向处理。本仓库目前尚未发布生产签名安装目录及自动续签流程。不要把源 JSON 文件填入 `plugins.catalog_url`。

[分发提案](marketplace-design.zh-CN.md)介绍共享目录和兼容导出。未实现部分不作为现有宿主的强制要求。
