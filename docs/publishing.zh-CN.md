# 插件发布

[English](publishing.md) · **简体中文**

本指南定义维护中的插件发行流程。公共分发状态见[项目 README](../README.zh-CN.md)，共享目录格式见[市场提案](marketplace-design.zh-CN.md)。

## 准备发行版本

选择 `zboard` 分支上已评审且检查通过的源码提交，并记录：

| 发行信息 | 必要内容 |
| --- | --- |
| 身份 | 插件 ID、发布者、语义版本和源码提交 |
| 兼容性 | 宿主版本范围、SDK/API 与页面桥版本、支持的平台 |
| 变化 | 用户可见行为、配置变化、数据迁移和恢复说明 |
| 验证 | 自动检查、宿主生命周期测试、目标平台运行和提供方联调结果 |
| 构建来源 | 工具链版本与宿主打包器提交 |

根据实际验证的宿主构建，复核 manifest 中推荐和已测试的宿主版本。认证插件还需记录是否完成真实提供方授权。交叉编译、协议 fixture 与部署运行分别覆盖不同检查。

标签按宿主与插件区分，例如 `zboard/oauth/v0.2.0`。已发布版本和制品内容不可替换，修正通过新版本发布。构建使用已提交源码和锁定依赖，不使用本地 workspace 替换。

## 签名安装包

发行密钥保存在受保护的签名环境中，Pull Request 检查不得访问这些密钥。发布者 ID 与公钥需要可信的分发渠道和明确的轮换流程。

在 `zboard/oauth/` 中运行：

```sh
python3 scripts/package.py --zboard /path/to/zboard --key /secure/publisher.key --key-id your-publisher --platform linux-amd64
```

打包器组装界面和目标运行组件，对内容文件计算摘要，并签名 manifest。发布前检查文件清单，验证签名和整个包的 SHA-256；随发行版本公布摘要和验证说明。

开发包使用 `--dev-key`，固定发布者 ID 为 `oauth-local-dev`，仅用于测试环境。平台代码签名与公证独立于插件的 Ed25519 签名。

## 发布目录

1. 在最终下载位置发布内容不可变的安装包。
2. 根据实际发布字节与 SHA-256 摘要生成目录条目。
3. 使用受信任的目录密钥签名目录。
4. 在宿主中使用公开目录和下载路径验证安装。

当前 ZBoard 下载器要求公网 HTTPS 443，拒绝查询参数、重定向、内网目标和环境代理。制品应使用满足这些条件的直达地址。GitHub Release 资产地址可能重定向，因此需要兼容的分发端点。

### ZBoard v1 目录

| 约束 | 内容 |
| --- | --- |
| Schema | `schema_version: 1` |
| 条目 | 最多 200 条，每个插件 ID 一条 |
| 有效期 | 未来 UTC 时间，距校验时刻最多 31 天 |
| 安装包 | 与目录身份和摘要一致的签名 `.zbplugin` |

当前 OAuth 打包器每次只构建一个平台。v1 分发应选择明确的平台专用目录，或提供经过单独验证、包含多个平台运行组件的包。同一目录不能重复列出相同插件 ID。当前脚本尚未自动实现多平台合包和目录发布。

维护者需保证目录可访问，并在到期前重新签发。目录过期后，新的市场安装会被拒绝。

## 撤回发行版本

密钥泄露或制品存在缺陷时，停止推荐受影响版本，并公布相关摘要、影响与恢复说明。与宿主维护者协调处置。移除市场条目不会自动停止已安装插件或删除数据，已有安装应按宿主支持的操作处理。
