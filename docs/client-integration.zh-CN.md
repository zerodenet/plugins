# 客户端接入范围

[English](client-integration.md) · **简体中文**

**状态：设计范围。** 本文列出构建与分发 ZNet Sink 插件前所需的宿主契约，不定义已实现的 API 或包格式。

## 宿主职责

ZNet Sink 拥有本地配置、系统权限决策、连接生命周期、凭据和对 Zero 内核的请求。插件通过带版本的能力请求明确的客户端操作，客户端先检查调用者、资源范围、实例状态和策略，再执行请求。

运行时需按执行模型定义隔离，包括进程或 WebView 访问、文件系统与网络访问、资源限制，以及客户端停止时的行为。ZBoard 的服务运行时和后台能力不授予客户端权限。

## 必要契约

| 范围 | 需要确定的事项 |
| --- | --- |
| 身份与包 | 客户端宿主标识、manifest schema、API 兼容性、签名和平台选择 |
| 扩展贡献 | 支持的界面位置与带版本的客户端操作 |
| 配置与数据 | 密钥处理、私有存储、迁移、备份和清除策略 |
| 生命周期 | 安装、启用、升级、失败恢复、停用与卸载 |
| 执行 | 隔离、系统权限、资源归属和终止 |
| 分发 | 目录兼容、制品托管、更新选择和离线导入 |

这些契约先在客户端项目定义并完成宿主验证，再在此实现插件。共享发现遵循[市场提案](marketplace-design.zh-CN.md)，使用客户端专用包和准入检查。

## 实现验收

客户端插件贡献需注明所用宿主 API，提供构建和测试命令，并在支持的平台上验证生命周期与失败行为。在线安装与离线导入都应检查包签名、宿主兼容性和能力。

源码在本分支的 `znet-sink/<plugin>/` 维护。实现变更和发行版本以 `znet-sink` 为目标，共享平台政策变更以 `main` 为目标。
